# FeatherPad vs Sublime Text — 2026-09-12

FeatherPad uses less memory on all six fixtures. Sublime responds earlier on editable 1–8 MiB documents; FeatherPad's 1 MiB CSV startup is a repeatable weakness. Large-file results compare different capabilities: FeatherPad uses a read-only bounded viewport above 8 MiB.

## Environment and method

- Windows, Intel Core i9-13900HX, 34,038,341,632 bytes physical RAM (31.7 GiB).
- FeatherPad 0.2.0 release executable; Sublime Text build 4200.
- Three fresh-process trials per application/file, alternating application order by round. Both applications warmed up once; each input streamed before launch to warm the filesystem cache. This is not a cold-disk benchmark.
- Sublime installation copied into an isolated portable directory with its own `Data` folder, no third-party plugins, hot exit/session restoration/update checks disabled. All Sublime child processes included (four processes versus FeatherPad's one).
- Default editor view, no Markdown preview or terminal. Repeated synthetic Markdown headings/prose/Rust fences; CSV includes Chinese and quoted commas. Real files, not sparse allocations. These fixtures do not represent every real document.
- All 36 trials reached the settling condition within the 60-second timeout.

## Results

Medians of three runs. Response is a visible window with the filename in its title answering `WM_NULL`, polled approximately every 50 ms. It is **not first paint, complete loading, or editing readiness**. Memory is aggregate process-tree private committed memory, not physical RAM usage.

| File | FeatherPad response (ms) | Sublime response (ms) | FeatherPad private (MiB) | Sublime private (MiB) |
|---|---:|---:|---:|---:|
| Markdown 1 MiB | 259 | 213 | 8.02 | 64.94 |
| Markdown 8 MiB | 1,210 | 210 | 44.73 | 92.07 |
| Markdown 64 MiB* | 108 | 208 | 3.43 | 192.24 |
| Markdown 1 GiB* | 106 | 157 | 3.40 | 2,346.46 |
| CSV 1 MiB | 4,370 | 210 | 6.99 | 54.23 |
| CSV 64 MiB* | 106 | 209 | 2.95 | 99.44 |

*FeatherPad opens files larger than 8 MiB in a read-only bounded viewport; Sublime follows its normal full-document loading path. This is not an equivalent editable-buffer comparison. The lower FeatherPad memory above 8 MiB reflects that mode switch. The 51 ms difference on 1 GiB is approximately one polling interval; avoid interpreting it as a precise speed ratio.

| File | FeatherPad settling (s) | Sublime settling (s) | FeatherPad working set sum (MiB) | Sublime working set sum (MiB) |
|---|---:|---:|---:|---:|
| Markdown 1 MiB | 2.65 | 3.17 | 26.19 | 123.14 |
| Markdown 8 MiB | 3.71 | 6.28 | 62.78 | 148.20 |
| Markdown 64 MiB | 2.64 | 4.27 | 21.52 | 247.31 |
| Markdown 1 GiB | 2.64 | 31.15 | 21.48 | 2,333.65 |
| CSV 1 MiB | 6.82 | 3.17 | 25.34 | 111.85 |
| CSV 64 MiB | 2.64 | 3.18 | 21.17 | 156.36 |

Settling means four consecutive half-second samples with less than 25 ms aggregate CPU consumption per sample and a responsive window. It includes approximately two seconds of observation overhead and is a heuristic, not proof of full load. Working-set sums may double-count shared pages. Sampled peaks in the raw data use 0.5-second intervals and can miss brief spikes. A one-second idle CPU sample is too short for a reliable power-efficiency conclusion.

FeatherPad CSV response ranges were 4,309–4,374 ms; Sublime 209–213 ms. FeatherPad 8 MiB Markdown ranged 1,198–1,247 ms; Sublime 208–215 ms. Both slowdowns reproduced in all three runs. CSV highlighting differs: FeatherPad colors columns; no CSV/TSV-specific file was found in the installed Sublime default package archives. This does not isolate highlighting cost or identify the cause of the delay.

## Interpretation and next work

The memory objective is working on these fixtures. The next optimization target is the editable-file opening path, especially the 1 MiB CSV case, followed by Markdown near the 8 MiB threshold. Profile file decoding, RichEdit text insertion/layout, and highlighting separately before choosing a fix. No application code was changed by this benchmark.

Scrolling FPS, input latency, selection, preview rendering, PDF, image loading, and terminal performance were not measured. The results cannot establish overall UI smoothness or that a 1 GiB Markdown document is fully editable/rendered instantly.

## Reproduce and audit

From the repository root on Windows with Python installed:

```powershell
python scripts/benchmark-editors.py --rounds 3 --sublime 'D:/softwares/Sublime Text'
```

The script creates about 1.2 GiB of fixtures plus a portable Sublime copy under `tmp/editor-benchmark/<timestamp>/`, opens test instances, and closes them after sampling.
